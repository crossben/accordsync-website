# Flutter

Accord has Dart packages that speak the same protocol and merge by the same rules as the TypeScript
packages, so Flutter devices sync through the same server as web and React Native devices. They
live in their own repository, [crossben/accordsync-dart](https://github.com/crossben/accordsync-dart).

| Package              | What it is                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| `accordsync_flutter` | Storage on the device with drift, widgets, and sync that follows the app lifecycle. Re-exports the two below. |
| `accordsync`         | The client. Pure Dart: also works in command-line tools and servers.                                          |
| `accordsync_core`    | The merge core.                                                                                               |

## Install

```sh
flutter pub add accordsync_flutter drift_flutter
```

## Open the client

Declare the same schema as your server, then open the client with drift storage and the HTTP
transport.

```dart
import 'package:accordsync_flutter/accordsync_flutter.dart';
import 'package:drift_flutter/drift_flutter.dart';

final schema = defineSchema({
  'dossier': {
    'client_name': lww(),
    'visits': counter(),
    'docs': set(),
    'status': conflict(),
  },
});

Future<AccordClient> openAccord(Future<String> Function() getToken) => AccordClient.open(
  schema: schema,
  storage: DriftStorage(AccordDatabase(driftDatabase(name: 'accord')), closeDatabase: true),
  transport: HttpTransport(url: 'https://sync.example.com', getToken: getToken),
);
```

Leave `deviceId` unset: the client generates one with a secure random source and stores it. To keep
Accord in your app's existing drift database instead, pass it: `DriftStorage(appDatabase)`. Accord
adds four tables prefixed `accord_` and needs no code generation.

## Sync around the app lifecycle

`AccordLifecycle` syncs in the foreground, pauses in the background, and syncs at once when the
network comes back. Accord has no connectivity dependency: give it a stream from the package you
already use.

```dart
runApp(
  AccordProvider(
    client: accord,
    child: AccordLifecycle(
      client: accord,
      online: Connectivity().onConnectivityChanged.map(
        (r) => !r.contains(ConnectivityResult.none),
      ),
      child: const FieldApp(),
    ),
  ),
);
```

Writes never wait for any of this: `await accord.inc(…)` completes as soon as the change is saved on
the phone, online or not.

## Widgets

```dart
RecordBuilder(
  record: 'dossier:91',
  builder: (context, fields) => Text('${fields?['visits'] ?? 0} visits'),
)
```

- `RecordBuilder` rebuilds when that record changes on the device: a local write, a sync, a rolled
  back refusal, or the record leaving the user's scope. `fields` is null for a record the device
  has never seen; fields with no value are absent.
- `ConflictsBuilder` gives every `conflict()` field holding more than one value. Show the values
  where someone can decide, then call `accord.resolve(record, field, value)`.
- `SyncStatusBuilder` gives the pending writes, the last sync and the last error.
- `accord.refusals` is a stream of writes the server refused. They are already rolled back; tell
  the user.

## Same behaviour as TypeScript

The Dart core passes the golden vectors in [`vectors/`](../vectors/) in every delivery order, and
reproduces byte for byte the snapshots of random scenarios generated by the TypeScript core
(`vectors/random/`). A test in the Dart repository runs Dart and TypeScript clients together against
the real server through a network that loses requests and responses, and checks every device ends
with identical data.

## Check list

- [ ] The schema is identical to the server's.
- [ ] `getToken` returns a fresh token; Accord calls it before every request.
- [ ] Refusals are shown to the user (`accord.refusals`).
- [ ] Conflicts are shown where the user can decide (`ConflictsBuilder`).
- [ ] The device database is protected like the rest of your app's data. Accord does not encrypt it.
