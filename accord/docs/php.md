# PHP

Accord has a PHP server that speaks the same protocol, merges by the same rules and uses the same
PostgreSQL schema as `@accordsync/server`, so every Accord client (TypeScript, React Native,
Flutter, Python, Java) syncs with it unchanged. Serve sync from your Laravel or Symfony backend instead of
running a Node.js service. It lives in its own repository,
[crossben/accordsync-php](https://github.com/crossben/accordsync-php).

| Package              | What it is                                                                              |
| -------------------- | --------------------------------------------------------------------------------------- |
| `accordsync/laravel` | Laravel integration: service provider, config, routes, artisan commands, scheduler.     |
| `accordsync/symfony` | Symfony integration: bundle, configuration, route loader, console commands.             |
| `accordsync/server`  | The sync server on PostgreSQL, framework-agnostic (PSR-15). The two above build on it.  |
| `accordsync/core`    | The merge core: hybrid logical clocks, operations, `lww`, `counter`, `set`, `conflict`. |

PHP 8.3+ with `pdo_pgsql`, and PostgreSQL.

## Install

```sh
composer require accordsync/laravel
php artisan vendor:publish --tag=accord-config
```

With Symfony, `composer require accordsync/symfony`; for plain PHP or another framework,
`composer require accordsync/server`.

## Define the server

`AccordServer::define()` takes the same parts as `defineServer` in TypeScript: the schema, a scope
function per record type, the access a user gets from their JWT claims, and how tokens are checked.
In Laravel, `config/accord.php` names an invokable class that returns it
(`'definition' => App\Accord\Definition::class`); its parameters are injected by the container.

```php
namespace App\Accord;

use Accord\Core\Schema;
use Accord\Server\{Access, AccordServer, Auth, ScopedRecord, ServerDefinition};
use Illuminate\Contracts\Cache\Repository;

final class Definition
{
    public function __invoke(Repository $cache): ServerDefinition
    {
        return AccordServer::define(
            schema: Schema::define([
                'dossier' => [
                    'agent' => Schema::lww(),
                    'visits' => Schema::counter(),
                    'docs' => Schema::set(),
                    'status' => Schema::conflict(),
                ],
            ]),
            scopes: ['dossier' => fn (ScopedRecord $r) => ScopedRecord::key('agent', $r->fields['agent'] ?? null)],
            access: fn (array $claims) => new Access(read: ["agent:{$claims['sub']}"], write: ["agent:{$claims['sub']}"]),
            // The JWKS is cached in Laravel's cache, shared by every worker.
            auth: Auth::jwks('https://auth.example.com/.well-known/jwks.json', issuer: 'https://auth.example.com/', audience: 'accord', cache: $cache),
        );
    }
}
```

The routes are `/accord/health`, `/accord/v1/push` and `/accord/v1/pull` (the prefix is
configurable): clients use `https://your-app/accord` as their server URL. They are stateless, outside
the `web` middleware group, and authenticate with the bearer token only.

In Symfony, the same `AccordServer::define(...)` call goes in a service implementing
`Accord\Symfony\DefinitionProvider`, and `config/routes/accord.yaml` imports the routes with
`type: accord`. Without a framework, `AccordServer::handler()` returns a PSR-15 request handler; see
the [`accordsync/server` README](https://github.com/crossben/accordsync-php/tree/main/packages/server).

## Migrations and compaction

```sh
php artisan accord:migrate      # Symfony: bin/console accord:migrate; plain PHP: vendor/bin/accord migrate
php artisan accord:compact      # Symfony: bin/console accord:compact; plain PHP: vendor/bin/accord compact accord.php
```

The migrations are the TypeScript server's, in the same ledger: a database migrated by either server
is up to date for the other. In Laravel, the provider registers `accord:compact` with the scheduler
at the definition's compaction interval (default hourly); elsewhere, run it from cron. Compaction
takes a PostgreSQL advisory lock, so overlapping runs do not conflict.

Use a persistent database connection (or `ACCORD_DATABASE_URL`, which Accord opens as persistent):
otherwise every sync request opens a PostgreSQL connection. Each PHP worker handles one request at
a time, so the worker pool size bounds concurrent pushes.

## Same behaviour as TypeScript

The PHP core passes the golden vectors in [`vectors/`](../vectors/) in every delivery order, and
reproduces byte for byte the snapshots of random scenarios generated by the TypeScript core. In the
PHP repository's CI, the [server conformance suite](../conformance/README.md) runs against the PHP
server and against its Laravel and Symfony example apps. A mixed-server fleet test runs the
TypeScript and PHP servers on one database at the same time, with TypeScript devices sending each
request to either server through a network that loses requests and responses, and checks every
device ends with identical data.

## Check list

- [ ] The schema is identical to the clients'.
- [ ] Production auth uses `Auth::jwks()` with an issuer and an audience; `Auth::hs256()` is for
      development and tests.
- [ ] `accord:migrate` runs on deploy, and compaction is scheduled.
- [ ] The database connection is persistent.
- [ ] Rate limits use a store shared by every server (Laravel: a cache store with atomic locks;
      Symfony: a shared cache pool and lock factory).
- [ ] Clients point at `https://your-app/{prefix}`.
